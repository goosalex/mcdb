2. Answers needed from you

These are decisions the executing agents were not authorised to make, or that Oracle source alone cannot settle. The first three unblock the remaining red tests immediately; the rest gate Phase 3 and Phase 4.

Immediate (unblocks green)

Q1. May the 4 tt.ticket_interface fixture defects be amended now? Each needs an edit under migration/test/pgtap/, which the anti-circularity rule reserves for explicit, ledgered amendments (A-009..). The edits add a missing column, move a value to the right column, and change one status 4 → 2. Nothing asserted changes. Alternative: leave red until Phase 4 revisits TICKET_INTERFACE.
Q2. Regenerate the 4 regress golden files, or filter CONTEXT lines in the runner? Recommendation on record: regenerate the goldens (the osag_notify one additionally needs the non-deterministic DETAIL line masked). Filtering would weaken the diff contract for every future package.
Q3. S-AUTH-007: wait for the Phase 3 plog shipper, or amend the test now? Waiting keeps the assertion as the acceptance case for XCUT-02's rollback-survival requirement. Amending (e.g. testing the log outside a caught block) makes auth.osag_auth green today but removes that natural test.

Phase 3 cross-cutting decisions (XCUT-01..06)

Q4. Exception codes. Ratify P0002/P0003 for NO_DATA_FOUND/TOO_MANY_ROWS corpus-wide? Assign real custom SQLSTATEs to Oracle -20801 (unknown dbprop), -20980 (ticket_closed), -20981/-20982 (ticket scheduling), and the unnumbered e_abort? All currently fall to generic P0001. Should the message-parity shim (14 sites) that reproduces Oracle's literal "no data found" text be kept?
Q5. plog as UDP shipper. Target host/port and datagram format? What replaces osag.plog_stub_log as the sink tests can assert on (every pilot test that reads it must be rewritten if nothing does)? What should who_called_my_caller() return in PostgreSQL (currently always NULL)?
Q6. Autonomous transactions. tt.util.close_old_dev_tickets now commits the caller's work too. Accept that delta, emit a UDP telemetry event instead, or use dblink as last resort? Same decision needed for mcdb_checks_consistency.insert_result, not yet traced.
Q7. How should a PostgreSQL instance identify itself as "dev"? close_old_dev_tickets reads Oracle V$INSTANCE. Options: a GUC such as mcdb.instance_role, a config table, or a database-name convention.
Q8. FUNCTION vs PROCEDURE (pg_kind). The pilot found no mismatch across 76 routines; may name-map.csv's pg_kind be treated as final for them, pending the corpus-wide COMMIT audit?

Scope and fidelity decisions

Q9. Dynamic SQL allowlist scope in tt.event_interface.exec_event_type_actions: restrict to the four TT.ESCALATION_INTERFACE routines seen in current data, or allow any single-NUMBER-argument procedure in a configured schema?
Q10. Private routine naming. Private package routines are currently emitted as tt.osag_notify__name (double underscore) with REVOKE ALL FROM PUBLIC. Confirm as the corpus-wide convention and fold into the name-map generator?
Q11. Reproduce or fix known Oracle bugs? (a) moveevent ignores p_event_id (source says "BROKEN, never run"); (b) add_status_change_event never assigns cust_id, so every status-change audit event has company_id = NULL; (c) expire_status doc says it calls change_label, body does not; (d) add_related_file checks same-company, remove_related_file does not. All are translated as-is today.
Q12. Materialized views auth.permission / auth.mv_service_access. Oracle refreshed them ON COMMIT; PostgreSQL does not. They gate authorization checks. Cron refresh, trigger-maintained, or convert to plain views?
Q13. Is SYS.OSAG_TABLE_REDEFINITION in the milestone? It wraps DBMS_REDEFINITION with 43 state variables and has no PostgreSQL analogue.
Q14. Is auth.osag_auth.grant_role dead code? It is marked deprecated and redirects to role 1000. Static analysis cannot see application callers.
Q15. Empty-string columns in production. Can mss.key.name, tt.ticket.customer_reference, or tt.event.details_public ever hold '' in production data? The translations normalise at the boundary either way, but a yes/no lets Phase 4 drop or keep that pattern.

3. What should be changed

Before Phase 4 starts (from METHOD-REVIEW.md, each backed by a reproduced defect)

  1. Lint rule banning 3-argument throws_ok(sql, sqlstate, text) in trace_lint.py. This single pgTAP ambiguity caused 3 amendment sweeps and 49 broken assertions (A-001, A-002, A-006).
  2. Checklist item: is() expected literals must be cast to the live column type (smallint vs numeric killed 54 assertions by cascade in A-003 and A-007).
  3. Require every "did NOT happen" assertion to sit next to a "call succeeded" assertion in the same test block. 6 such assertions pass vacuously today when separated.
  4. provenance_lint.sh must assert the amendments ledger exists at migration/spec/TEST-AMENDMENTS.md. It lived at the wrong path for the whole phase without detection.
  5. Make template staleness a hard gate. run-all.sh only warns when schema-fixes/ changed after mcdb_tmpl was built. Content-hash the directory and rebuild automatically. A stale template silently dropped 5 assertions in plan 02-12.
  6. Spec template field for structurally inert SELECT INTO STRICT sites (FROM-less scalar selects, unique-key lookups) so mutation testing picks real targets.

Test and harness fixes (pending Q1–Q3)

  • Amend the 4 selectinto.sql fixtures (A-009) and record them in the ledger.
  • Regenerate 4 regress goldens; mask the non-deterministic DETAIL values in tt__osag_notify__errors.out.
  • Add TT.ESCALATION_INTERFACE ↔ TT.EVENT_INTERFACE to known_cycles.json. The dynamic-SQL trace found this second mutual recursion; the lexer cannot see it, so the wave order currently ignores it.
  • bootstrap.sh's database-name allowlist (^mcdb_(test|tmpl|harness)) disagrees with the pattern CLAUDE.md describes. Align the documentation; two plans tripped on it.

Schema and ora2pg output (Phase 5 brief, SCHEMA-FIXES.md)

  • ddl/migrated/ contains no CREATE SEQUENCE at all (309 sequences ported by hand in bootstrap/30_sequences.sql). Fix the ora2pg configuration or ship the port.
  • tables.pg.sql and views.pg.sql begin with \set ON_ERROR_STOP OFF, so a naive load reports success while silently skipping broken statements.
  • ora2pg emits schema-qualified index names (CREATE INDEX AUTH.IDX_… ), which PostgreSQL rejects. Fixed locally for the three auth MVs only.
  • ddl/migrated is an older export than changes/changelog-current.sql: tt.event/tt.ticket.contact_zitadel_id are missing and were added by schema-fix. Regenerate the migrated DDL from the current baseline.
  • The 843 FK constraints are loaded from the deferrable variant; the non-deferrable tables/constraints.pg.sql is skipped. Decide which one ships.
