<objective>
Translate `TT.OSAG_NOTIFY` to PL/pgSQL and satisfy the suite plan 02-05 wrote against its spec.

Purpose: This is the SELECT INTO verdict. 30 sites, one TOO_MANY_ROWS handler, 11 OTHERS
handlers. Pitfall 1 — Oracle's `SELECT INTO` raises on zero rows; PL/pgSQL's does not unless
you write `STRICT` — is the most likely way this migration silently changes behaviour across
the whole corpus, and this is the package where the pilot finds out whether the method catches
it. The tests were written to fail against a translation that took the easy blanket answer in
either direction. Do not take it.

Output: `migration/pgsql/tt/osag_notify.sql` + FINDINGS. Suite green (modulo cycle siblings).

<the_rules_for_translation_plans>
1. **You may not modify any file under `migration/test/`.** `provenance_lint.sh` checks git

   line-by-line structure rather than the Oracle source's control flow.
3. **Object names come verbatim from `migration/mapping/name-map.csv`.**
4. **Every `SELECT INTO` gets the verdict its spec assigned — per site.**
5. **No Oracle vendor-package identifiers survive.** The acceptance criteria grep for them.
</the_rules_for_translation_plans>

<known_ground_truth>
- 6 public routines (`event_notify` first) + **13 private**. The private-routine naming
  convention was declared by plan 02-05 in the spec's front-matter — **use it, do not invent a
  second one.** A second convention here becomes a second convention in Phase 4's 44 packages.
- **30 SELECT INTO sites**, each with a verdict in the spec's `### SELECT INTO strictness` table.
- **1 TOO_MANY_ROWS handler** — the only one in the pilot. Oracle EXPECTED a multi-row case
  there, which means `STRICT` is mandatory at that site: without it PL/pgSQL silently takes the
  first row and the handler becomes dead code.
- **11 OTHERS handlers.** Some swallow (a notification failure is deliberately non-fatal to the
  caller), some log-and-reraise. The spec has the verdict per handler. Getting a swallow wrong
  as a re-raise means tickets start failing to save; getting a re-raise wrong as a swallow means
  errors vanish. Both are silent in a happy-path test suite. Neither is silent in the suite
  02-05 wrote.
- **51 `%TYPE` references** — the spec lists them. Each must resolve against the MIGRATED schema.
  Some may not (Pitfall 10); those are schema fixes, not translation workarounds.
- No COMMIT, no ROLLBACK, no autonomous transaction, no package state.
- Oracle body: **1844 lines.** Member of the four-package TT cycle group; called by
  `AUTH.OSAG_AUTH`, `TT.EVENT_INTERFACE`, `TT.TICKET_INTERFACE`.
</known_ground_truth>
