- Phase 2 does NOT require a test per routine as a coverage mandate — VER-02 is Phase 4's.
  But 38 routines with 3 tests would be a pilot that proved nothing, so this plan requires at
  least one citing test per routine. That is the pilot earning its name.

    Write `tt__ticket_interface__changes.sql` covering the remaining ~27 routines: the whole

    `add_*`/`remove_*` pairs (docs_page, related_ticket, related_file), and the todo-list
    routines (`clear_todo_list`, `add_todo_item`, `update_todo_item_status`).

    Two things this suite must do that nothing else will:

    **1. The `change_label` overload pair.** Call BOTH signatures and assert that each did its
    own thing. A test that calls only one, or that calls both but asserts the same outcome,
    would pass against a translation that dropped one of the two — and dropping one is exactly
    the plausible mistake, since they flatten to the same PostgreSQL name. Assert distinctly.
    This is the only place in the entire pilot where PostgreSQL's native overloading is
    exercised, and `migration/README.md` singles it out as the corpus's one legitimate overload.

    **2. Empty-string vs NULL.** The spec's checklist enumerates every VARCHAR2 parameter where
    Oracle collapsed `''` and NULL into the same value: `change_subject`, `change_summary`,
    `change_label`, `change_customer_reference`, `change_partner_reference`, and any others it
    found. For EVERY one of them, write a paired assertion: call with `''`, call with NULL,
    and assert the stored result is identical wherever the spec says Oracle made them
    identical. PITFALLS.md names the exact failure mode: *"Test suites that only insert NULL
    and never insert `''` for string columns (the gap won't be caught)"*. In PostgreSQL, `''`
    is a real zero-length string that satisfies NOT NULL — so a translation that forgot to
    normalise at the boundary will store `''` where Oracle stored NULL, and every downstream
    `IS NULL` check silently stops matching. Nothing else in this phase catches that. This
    suite does.
  </action>
