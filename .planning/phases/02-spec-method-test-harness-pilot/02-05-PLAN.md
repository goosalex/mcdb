<objective>
Spec `TT.OSAG_NOTIFY` from Oracle source and write its tests — before its translation exists.

Purpose: This package is the pilot's SELECT INTO proving ground. It has **30 `SELECT ... INTO`
sites** — the single richest concentration of the NO_DATA_FOUND/STRICT trap anywhere in the
pilot — plus the only `TOO_MANY_ROWS` handler in the entire pilot dependency set. Pitfall 1 is
the most likely way this whole migration silently corrupts behaviour: in Oracle a zero-row
`SELECT INTO` raises; in PL/pgSQL, without `STRICT`, it silently assigns NULL and carries on.
If the uniform checklist cannot handle this package, it cannot handle the corpus.

`OSAG_NOTIFY` is also a transitive dependency, not one of the four packages the user named —
but three of the four pilot packages call it, so it gets a full spec and a full translation.
It is not free and it is not optional.

Output: one spec, two pgTAP suites, one expected-output suite. **All red.**
</objective>

  TOO_MANY_ROWS handler in the whole pilot is in this package. Find it and spec it — a

  the PL/pgSQL translation needs `STRICT` there or it will silently take the first row.
- 51 `%TYPE` references (`type_refs`) — the highest in the pilot. Pitfall 10 applies: each one
  must resolve against the MIGRATED schema, not the Oracle one. Some may not.
- No COMMIT, no ROLLBACK, no autonomous transaction, no package state. `static_resolution:
  complete`.
- Size: spec 130 lines, body **1844 lines**. This is a big read. Budget for it.
- It is a member of the four-package TT cycle group.
</known_ground_truth>

<design_decision_you_must_make>
**The 13 private routines.** `name-map.csv` covers public routines only, by design. Oracle
private package routines have no PostgreSQL equivalent scope. Pick ONE convention, apply it
uniformly, and record it in the spec's front-matter and in the SUMMARY:
  (a) translate each as a schema-level function with a marker prefix (e.g.
      `tt.osag_notify__send_notification_by_type`, double underscore signalling "private"),
      with `REVOKE ALL ... FROM PUBLIC`; or
  (b) inline them into their callers.
Recommendation: (a). Thirteen routines is too many to inline without wrecking readability,
and Phase 4 will hit this in every package — so the convention you set here becomes the
corpus-wide convention. Whatever you choose, this is a NEW naming rule that lives OUTSIDE
`name-map.csv`, which is exactly the thing `migration/README.md`'s consumer contract warns
about. So write it down loudly in the SUMMARY and flag it as a Phase 4 decision that may
need to be folded back into the name-map generator.
</design_decision_you_must_make>
