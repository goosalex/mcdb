<objective>
Build the test database the pilot actually runs against: the real ora2pg schema from
`ddl/migrated/`, the sequences ora2pg forgot, realistic reference data from `masterdata/`,
and the throwaway `plog` stub every pilot package calls on its error paths.

Purpose: The locked decision is that the test schema IS `ddl/migrated/` — the genuine
migration target, known to contain errors — and that fixing the errors the pilot surfaces
is IN SCOPE. That is deliberate: it front-loads breakage that would otherwise ambush
Phase 5's container build. Every fix made here is recorded in a ledger so Phase 5 inherits
it rather than rediscovering it at the worst moment.

Output: a `mcdb_tmpl` template database, a schema-fix ledger, a masterdata loader, and
`migration/pgsql/osag/osag_plog.sql` (stub).
</objective>

<known_ground_truth>
Verified against the repo during planning — start from these, do not re-derive them:

- `ddl/migrated/tables/tables.pg.sql` (8410 lines) opens with `\set ON_ERROR_STOP OFF`.
  **Loading it as-is means every broken statement is silently skipped and the load still
  "succeeds".** Override this. A silent load is worse than a failing one.
- `ddl/migrated/` contains **no `CREATE SEQUENCE` anywhere.** The Oracle sequences live
  only in `ddl/generated/sequences/*.sql` (30 files). Grepping the pilot bodies finds at
  least these in use: `tt.event_sequence`, `tt.ticket_sequence`, `tt.ticketflow_seq`,
  `tt.changerequest_seq`, `tt.ticketdocspage_seq`, `tt.ticketrating_seq`, `tt.todoitem_seq`,
  `tt.ticketreqclassification_seq`, `tt.tickettimestatistic_seq`, `auth.seq_profile`,
  `auth.seq_user_company_scope`, `auth.seq_user_permission`. This is the first real ora2pg
  gap the pilot surfaces.
- Schemas and roles come from `ddl/migrated/users/*.sql` (each is a `DO $do$` block doing
  CREATE ROLE + CREATE SCHEMA AUTHORIZATION), not from `tables.pg.sql`.
- Constraints: `ddl/migrated/tables/constraints.pg.sql` and
  `ddl/migrated/constraints/{check,fk}-constraints.pg.sql`. Views: `tables/views.pg.sql`
  (known to carry Oracle ghost columns such as `sys_nc00008$` per CONCERNS.md).
- `masterdata/<SCHEMA>/` holds `<table>.csv` (quoted, header row = column names),
  `<table>.xml` (per-column `<column name= type=/>` declarations), plus `_pre.sql` /
  `_post.sql` which disable/enable specific constraints around the load.
  Counts: AUTH 16 csv, TT 14, MSS 51, MCAUDIT 6, OSAG 1.
- Oracle `OSAG.OSAG_PLOG` public surface (13 routines): `Emerg Alert Crit Err Warning
  Notice Info Debug` (each `(message IN VARCHAR2)`), `LevelAsString(NUMBER)->VARCHAR2`,
  `LevelAsNum(VARCHAR2)->NUMBER`, `Log(NUMBER, VARCHAR2)`, `LogRaw(NUMBER, VARCHAR2)`,
  and `AuditUsage(VARCHAR2,VARCHAR2,VARCHAR2)`. PostgreSQL names are in `name-map.csv`
  (`osag.osag_plog_*`). The public synonym is `plog`.
</known_ground_truth>

<design_decisions>
- **D-P5a — `plog` is a STUB (locked by the user).** It writes a row to a log table AND
  emits `RAISE NOTICE`. The table is what tests assert on; the NOTICE is for humans. The
  real UDP shipper is Phase 3 (XCUT-02) and this stub must not constrain its design.
- **`AuditUsage` is NOT implemented, not even as a no-op.** That is not a new decision —
  PROJECT.md, REQUIREMENTS.md (XCUT-06) and PITFALLS.md Pitfall 4.3 already record that
  the feature is unused (write-only; nothing reads `osag.plsql_audit`) and gets DELETED
  rather than ported. Creating a stub for it would imply the audit still works. Pilot
  translations therefore delete their AuditUsage call sites, and each spec records how many
  it deleted so Phase 3 can reconcile against the expected ~177 corpus-wide.
- **The stub's log row folds into the caller's transaction and is lost on rollback.** That
  is a real, deliberate limitation, and it is exactly why Phase 3 replaces it with UDP.
  Consequence for this phase, stated so no later plan trips on it: **pilot tests assert on
  plog output WITHOUT forcing a rollback.** Rollback-survival of logging is NOT a Phase 2
  claim; it is XCUT-02's test.
- **D-P7 — Schema fixes are additive files, never edits to `ddl/migrated/`.** `ddl/migrated`
  is the ora2pg artifact of record and stays untouched. Fixes live in
  `migration/test/schema-fixes/*.sql`, applied after the base load, and every one is
  written up in `migration/test/SCHEMA-FIXES.md` with the error it fixes, so Phase 5 can
  either apply the same fixes or push them back into the ora2pg configuration.
</design_decisions>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `ddl/migrated/**` (untrusted ora2pg output) → test database | Machine-generated SQL, known to contain errors, executed with superuser rights |
| `masterdata/**` CSV → test database | Data crosses into the DB via COPY |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-09 | Tampering | `\set ON_ERROR_STOP OFF` in `tables.pg.sql` | critical | mitigate | The loader strips the directive and forces `ON_ERROR_STOP=on`; a silently-skipped CREATE TABLE would let a false-green schema propagate all the way to Phase 5 |
| T-02-10 | Information Disclosure | masterdata CSV loaded into a shared dev DB | low | accept | Reference/lookup data only (types, statuses, countries) — no customer data. Rationale recorded |
| T-02-11 | Tampering | `DISABLE TRIGGER ALL` left on after a failed fixture load | medium | mitigate | Loader re-enables in a `try/finally`; `build-template.sh` asserts zero disabled triggers (`pg_trigger.tgenabled <> 'O'`) before marking the template |
| T-02-12 | Elevation of Privilege | plog stub with transaction control breaks FUNCTION callers | high | mitigate | Explicit acceptance test calls the stub from inside a PL/pgSQL FUNCTION body; a COMMIT in the stub fails it |
</threat_model>
