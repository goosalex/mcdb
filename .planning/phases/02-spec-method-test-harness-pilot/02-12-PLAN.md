<known_ground_truth>
- **38 public routines** (37 PROCEDURE, 2 FUNCTION), **3 private** (`add_status_change_event`,
  `handleDeferredTransitions`, `updateTicketTimeStats` — use the private-routine convention the
  OSAG_NOTIFY spec declared).
- **`change_label` is an OVERLOAD PAIR**: two Oracle signatures, ONE PostgreSQL object name, both
  rows marked `is_overload=true` in `name-map.csv`. PostgreSQL overloads natively — create BOTH.
  Dropping one would compile, load, and pass every test that only calls the other. Plan 02-08
  wrote a test that calls both and asserts distinct outcomes, precisely because this is the one
  place the linters cannot save you.
- **77 SELECT INTO sites**; 13 NO_DATA_FOUND handlers; 10 OTHERS handlers. Verdicts in the spec's
  `### SELECT INTO strictness` table.
- **The two FUNCTIONs**: `get_next_recent_ticket`, `replace_id_placeholders`. A PostgreSQL FUNCTION
  can never COMMIT and cannot CALL a procedure that does. `TT.UTIL` (same cycle group) COMMITs at
  Oracle lines 234/244. Plan 02-07's spec traced whether these FUNCTIONs reach it. Follow the
  spec's verdict.
- No COMMIT, no ROLLBACK, no autonomous transaction, no package state in this package itself.
- Sequences: `tt.ticket_sequence`, `tt.event_sequence`, `tt.ticketflow_seq`,
  `tt.changerequest_seq`, `tt.ticketdocspage_seq`, `tt.ticketrating_seq`, `tt.todoitem_seq`,
  `tt.ticketreqclassification_seq`, `tt.tickettimestatistic_seq`. Mechanical translation only
  (Pitfall 11 — no identity-column modernisation).
- **Mutually recursive with `TT.EVENT_INTERFACE`** (plan 02-11, same wave). PL/pgSQL does not
  resolve function calls at CREATE time, so your file loads regardless of load order.
</known_ground_truth>
