## Design Decisions (made here, stated plainly, reversible)

No CONTEXT.md or RESEARCH.md exists for this phase; these choices are the planner's, and each is cheap to reverse.

- **D-A — Artifact formats: JSON for inventory + graph, CSV for the name map.** The inventory and graph are nested (routines inside packages, edges with metadata) — JSON. The name map is flat, row-per-object, and is read by three independent consumers plus humans doing `grep`/diff review — CSV, per ARCHITECTURE.md Pattern 2. Reversible: the generators own the serialization.
- **D-B — Tooling: Python 3.12 stdlib only. No pip/npm/cargo installs. No ZPA/JVM.** Python 3.12.3, `jq`, and `node` are already on the box. The facts this phase needs (object headers, routine signatures, cross-object identifier references, semantic markers) are recoverable with a comment-and-string-stripping lexer plus targeted matching. ZPA (ANTLR PL/SQL parser, per STACK.md) would add a JDK + jar dependency for marginal gain at this stage. **Reversibility is protected by the artifact formats:** if Phase 2/4 spec derivation finds the lexer insufficient, ZPA can be swapped in behind the same `inventory.json` schema without touching any consumer. Because there are zero package-manager installs, the package-legitimacy gate does not apply to this phase.
- **D-C — Location: a new top-level `migration/` tree**, per ARCHITECTURE.md "Recommended Project Structure". Deliberately NOT `pg_migration/` — that tree holds untrusted ora2pg output and must not be confused with verified pipeline artifacts.
- **D-D — Generator AND output are both checked in.** Artifacts are regenerable, never hand-maintained. `migration/regenerate.sh --check` (plan 02) regenerates into a temp dir and diffs against the checked-in copies, failing if they are stale.

**Marker counts are NOT a reconciliation contract.** A naive `grep -io` over bodies+procs+triggers yields: `PRAGMA AUTONOMOUS_TRANSACTION` 6, `RAISE_APPLICATION_ERROR` 49, `NO_DATA_FOUND` 88, `WHEN OTHERS` 160, `AuditUsage` 176, `COMMIT` 13, `ROLLBACK` 2, `EXECUTE IMMEDIATE` 15, `DBMS_SQL` 16. These diverge sharply from the ROADMAP's "known scale markers" (~3 pragmas, ~9 RAISE_APPLICATION_ERROR, ~22 NO_DATA_FOUND, ~27 WHEN OTHERS) precisely because raw grep counts occurrences inside doc comments and string literals. **The lexer's comment/string-stripped count is the authoritative one.** Hard-gate on *structural* counts (files, objects, spec↔body pairing) which are exact; *report* marker counts as derived data alongside the naive-grep delta, do not assert equality against either prior.

    Implement three public entry points.

    1. `strip_noise(text) -> StrippedSource` — a length-preserving blanker. Walk the source once as a character-state machine over states {CODE, LINE_COMMENT, BLOCK_COMMENT, STRING, QUOTED_IDENT}. Replace every character inside a comment or a single-quoted string literal with a space, but preserve newlines verbatim so that byte offsets and line numbers in the cleaned text map 1:1 back to the original. Handle the doubled-quote escape inside string literals. Do NOT use a regex to remove comments — nested quote/comment interleavings in this source will defeat it. Expose `clean` (the blanked text), `raw` (original), and `line_of(offset)`. Every downstream matcher in this phase runs against `clean`, never `raw`.

    Also blank the Liquibase header lines (a leading double-hyphen directive is already a line comment, so this falls out of the comment handling for free) — but retain them in `raw` and expose `changesets` as a list of the `--changeset` author:id values with their line numbers, since a single file can carry many.

    2. `scan_objects(stripped, path) -> list[ObjectHeader]` — find every top-level object definition. `ObjectHeader` carries `kind` (one of: package_spec, package_body, procedure, function, trigger, type), `schema`, `name`, `start_line`, `end_line`, `source_path`. Match `CREATE [OR REPLACE] {PACKAGE|PACKAGE BODY|PROCEDURE|FUNCTION|TRIGGER|TYPE}` case-insensitively, tolerating an optional schema qualifier and optional `AUTHID` clauses.

    **The type case needs an explicit second pass.** Both files under `ddl/src/types/` build their type via a string argument to EXECUTE IMMEDIATE inside an anonymous block, so the `CREATE OR REPLACE TYPE` text lives inside a string literal — which `strip_noise` has just blanked. Handle this by scanning `raw` (not `clean`) for the DDL keyword *when and only when* it appears inside a string literal span whose enclosing statement is an EXECUTE IMMEDIATE, and mark the resulting header `wrapped_in_dynamic_sql: true`. Any object discovered this way is a genuine object and MUST appear in the inventory.

    Determine `end_line` by scanning forward to the next top-level object header or EOF — do not attempt to balance BEGIN/END, which nested blocks and case-insensitive END labels make unreliable.
