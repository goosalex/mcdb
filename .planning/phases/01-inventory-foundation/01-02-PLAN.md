## Naming Rules (decided here — these ARE the SSOT's semantics)

Derived from the `pg_migration/output/package_in_name/` prototype (shape only; its logic is untrusted) and PROJECT.md's `package_in_name` constraint. Schema layout stays identical to Oracle; only object names change.

| Oracle object | PG schema | PG object name | Example |
|---|---|---|---|
| Package routine `SCHEMA.PKG.OBJ` | `schema` (lower) | `pkg_obj` (lower) | `TICKETEVOLUTION.CALCULATOR.materialize_tickev` becomes `ticketevolution` . `calculator_materialize_tickev` |
| Standalone procedure `SCHEMA.PROC` | `schema` (lower) | `proc` (lower) — no prefix, it has no package | `SYS.decomAuthHost` becomes `sys.decomauthhost` |
| Trigger `SCHEMA.TRG` | `schema` (lower) | `trg` (lower) — no prefix | `APPID.t_interface_ps_link_class_sync` |
| Trigger function (PG needs one; Oracle has no such concept) | `schema` (lower) | `trg` + `_fn` (lower) | `appid.t_interface_ps_link_class_sync_fn` |
| Type `SCHEMA.TYP` | `schema` (lower) | `typ` (lower) — no prefix | `MCDB_MONITOR.consistency_check_result_type` |

The trigger-function row exists so Phase 4 does not invent trigger-function names outside the SSOT. Emitting it here is what keeps "one name map, no second mapping" true.

## Collision Semantics (the hard part — get this exactly right)

`package_in_name` flattening creates a real, concrete collision hazard in this schema, because several packages in the same schema are prefix-extensions of each other:

- `MC`: MONITORING, MONITORING_STATE, MONITORING_TICKET_PROCESSES
- `AUTH`: OSAG_AUTH, OSAG_AUTH_STATE, OSAG_AUTH_PASSPORT
- `TT`: EVENT_INTERFACE, EVENT_INTERFACE_STATE, TICKET_INTERFACE, TICKET_INTERFACE_STATE
- `MSS`: OSAG_DBPROP, OSAG_DBPROP_STATE, OSAG_IP, OSAG_IP_TEST
- `GUMA2`: OSAG_GUMA, OSAG_GUMA_STATE

A routine `state_foo` in package `MC.MONITORING` and a routine `foo` in package `MC.MONITORING_STATE` both flatten to `mc.monitoring_state_foo`. The collision gate exists for exactly this.

Classify every duplicate `(pg_schema, pg_object_name)` group:

| Case | Condition | Disposition |
|------|-----------|-------------|
| Legitimate overload | All rows come from the SAME Oracle package AND the same routine name, with DISTINCT normalized argument-type lists | ALLOWED. Mark every row `is_overload=true`. PostgreSQL overloads natively. (`TT.TICKET_INTERFACE.change_label` is the known real instance.) |
| Hard collision — identical signature | Two or more rows share `(pg_schema, pg_object_name, oracle_signature-arg-list)` | HARD FAIL. Exit non-zero. Unresolvable without a human decision. |
| Hard collision — cross-package prefix ambiguity | Rows share `(pg_schema, pg_object_name)` but come from DIFFERENT Oracle packages, even when the argument lists differ | HARD FAIL. Two unrelated routines masquerading as overloads of one function would silently mis-dispatch. |

A hard collision is resolved ONLY by a human adding a row to `migration/mapping/overrides.csv`. The generator applies overrides; it never invents a disambiguating name on its own. `--check` fails if any hard collision lacks a matching override row, and also fails on a stale override row that matches no collision.

## Cycle Policy (decided here)

Oracle packages CAN be mutually recursive, so a cycle is not automatically a bug and must not hard-fail the topological sort. Policy:

- Detect strongly-connected components. Any SCC of size greater than 1 is a cycle group.
- Collapse each cycle group into one condensed node for the topological sort. All its members share one wave number and each carries `cycle_group: "<id>"`.
- Every cycle group is printed loudly by `--check` and must be listed in `migration/analyze/known_cycles.json`. A cycle group NOT in that file fails the check — so the first run surfaces the real cycles for human acceptance, and any new cycle introduced later is a regression that breaks the build.
- Phase 4 must translate a cycle group's members together in one batch, since none of them can precede the others. `depgraph.json` states this per group so Phase 4 does not have to rediscover it.
